## Duplication, assumptions and hidden paths

1. Three evaluator layers (`run_eval`, `tdmpc.evaluation`, `comparison.evaluate`)
   share episode aggregation but differ in legacy protocols, state preservation,
   artifact identity and selection. Consolidating them now risks historical contract
   drift. Use comparison for independent cross-algorithm reporting.
2. Nominal 302/1/80 assumptions recur in loader, SAC wrapper and comparison aggregate.
   These are intentional guards until shifted protocol/schema support exists. Only
   TD-MPC's configuration-side checks and four live physics checks were extracted.
3. `CheckedEnv` also serves SAC and shared comparison. Compatibility alias
   `tdmpc.environment.CONTRACT` remains, so imports and serialized contract values
   remain valid. Generic adapter relocation is deferred.
4. Native action smoothing state is unobserved. No feature augmentation, action
   rescaling or reset change is introduced. Planning remains upstream stochastic
   sampling with the existing eval flags/seeding.
5. TD-MPC runner updates at episode boundaries and evaluates validation with
   `official_callback`; TD-MPC2 uses its own upstream trainer/seed warmup and train
   split evaluation. These paths must not be unified by renaming metrics.
6. TD-MPC2 Hydra composition changes cwd, sys.path and a Hydra helper; source imports
   use generic `common` and `envs`. Patched factories import the local adapter at
   runtime. Fresh child processes/workcopies preserve namespace isolation.
7. Observer/logger wrappers record actual environment calls separately from learner
   updates; TD-MPC2 `cfg.steps` loop bound is not the real interaction count.
8. Hash helpers, Tee implementations and W&B lifecycle repeat across algorithms.
   They are small **MERGE CANDIDATES**, with different artifact/version semantics;
   no benefit justifies broad edits in this preparation.
9. Some historical docs and TD-MPC2 worker reward-formula metadata say
   `mean(abs(Cl))`. The pinned 2D reward uses `abs(mean(Cl))`. The shared evaluator's
   live check and legacy CONTRACT already use the correct formula. Metadata is
   evidence of an annotation error, not different executed physics. Historical
   artifacts and the TD-MPC2 baseline are untouched; a future metadata correction
   should be versioned separately.
10. `CONTRACT` documents dt/CFL and the pinned source SHA but the old live validator
    checks only Re, control interval, lift penalty and smoothing. Extraction preserves
    that coverage/tolerance. It does not certify all solver parameters or claim an
    installed wheel equals the Git pin.
11. TD-MPC keeps only rolling latest/best/final; comparison cannot reconstruct
    overwritten checkpoints. Package CLIs also intentionally differ: TD-MPC packages
    small metadata; SAC can include binaries. They are not interchangeable duplicates.
